# HousePrices: сравнение разных моделей и фичей.

Задача — предсказать цену продажи дома по его характеристикам на данных соревнования Kaggle [House Prices – Advanced Regression Techniques](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques).

Цель - сравнить классические модели, градиентные бустинги, нейросети и ансамбли, а также оценить, как новые признаки влияют на качество прогнозов.

## Запуск

Для запуска требуется **Python**. В `requirements.txt` указана CPU-сборка pytorch.
Корректность запуска проверялась на Windows с Python 3.14, 3.11. CV оценки были получены на версии 3.11; при повторном обучении в другом окружении они могут отличаться.

После скачивания репозитория нужно открыть терминал в его корне - папке с `main.py` и `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

После установки зависимостей для повторного запуска достаточно последней команды.

### Что выполняется при запуске
1. Выполняется 5-фолдная кросс-валидация ElasticNet, CatBoost, LightGBM, MLP и MLPEmb. Затем эти модели обучаются на всей обучающей выборке.
2. По OOF-прогнозам CatBoost и LightGBM оценивается усреднение 50/50.
3. В консоль выводится итоговая таблица RMSE выбранных моделей и ансамбля.

Инференс можно запустить отдельно на сохранённых моделях `FINAL_*`.

Обучение и инференс настраиваются независимо. При `save_models=False` новые обученные модели не заменяют сохранённые `FINAL_*`, используемые для инференса.

Результат инференса находится в `inference_predicts/`:

```text
predictions_{experiment_name}_{model_name}.csv
```

Каждый CSV содержит столбцы `Id` и `SalePrice`, чего требуют условия сабмита.

## Данные и EDA

- `data/train.csv` - обучающие данные с целевой переменной `SalePrice`.
- `data/test.csv` - данные для предсказания; целевые значения не предоставлены.
- [EDA_House_Prices.ipynb](EDA_House_Prices.ipynb) - исследование распределений, пропусков, корреляций и связи признаков с ценой, с графиками и текстовыми выводами.

Основные выводы:
1) Среди признаков с наиболее высокой связью с ценой выделяются `GrLivArea`(надземная жилая площадь), `2ndFlrSF`(площадь второго этажа) и `OverallQual`(общее качество материалов и отделки).
2) Медианные цены также заметно различаются по `Neighborhood`(районам) и `KitchenQual`(качество кухни).
3) Часть пропусков отражает отсутствие объекта, например, забора или гаража.
4) Редкие категории, такие как оценки качества бассейна, представлены слишком малым числом домов для уверенного сравнения цен.

## Подготовка признаков

- Пропуски заполняются согласно конфигу.
- Для моделей, которым это требуется, числовые признаки стандартизируются.
- Для классических моделей и обычной MLP используется one-hot encoding (возможен выборочный OrdinalEncoding, но прироста это не дает).
- CatBoost получает категориальные признаки; для LightGBM столбцы приводятся к типу `category`.
- Для MLPEmb выбранные в конфиге категории кодируются индексами и передаются в обучаемые embedding-слои. Индекс 0 зарезервирован для неизвестных категорий. Остальные категории кодируются с помощью OneHot.
- Создается новый признак - произведение оценок качества и состояния дома (`OverallQual` * `OverallCond`).

Большинство новых признаков в моих экспериментах не улучшили метрику, а некоторые ухудшили ее.

В CV препроцессор обучается только на обучающей части соответствующего фолда. При инференсе применяется сохранённый обученный на всех данных препроцессор.

Проверенные признаки:

| Признак | Идея | Результат |
|---|---|---|
| `HouseAge` | Возраст дома на момент продажи (`YrSold - YearBuilt`) | Не улучшил RMSE по CV |
| `RepairAge` | Число лет между последним ремонтом и продажей (`YrSold - YearRemodAdd`) | Не улучшил RMSE по CV |
| `2ndFlrPresent` | Индикатор наличия второго этажа (`2ndFlrSF > 0`) | Не улучшил RMSE по CV |
| `GaragePresent` | Индикатор наличия гаража (`GarageArea > 0`) | Не улучшил RMSE по CV |
| `DateSold` | Комбинация года и месяца продажи (`YrSold` и `MoSold`) | Не улучшила RMSE ни при добавлении к исходным столбцам, ни при их замене |
| `LivAreaQual` | Произведение надземной жилой площади и оценки качества дома (`GrLivArea * OverallQual`) | Улучшил ElasticNet и немного ухудшил LightGBM, CatBoost |
| Доля отделанной площади подвала | Отношение отделанной площади к общей (`(TotalBsmtSF - BsmtUnfSF) / TotalBsmtSF`) | Немного улучшила ElasticNet, ухудшила CatBoost и LightGBM |
| `BathCnt` | Суммарное количество санузлов на надземных этажах и в подвале | Немного улучшил LightGBM, ухудшил CatBoost |
| `OverallQualCond` | Произведение оценок качества и состояния дома (`OverallQual * OverallCond`) | Снизил CV RMSE CatBoost с `0.118453` до `0.117971`. Оставлен в финальном наборе |
| `log1p(GrLivArea)` | Логарифмирование надземной жилой площади | Заметно улучшило ElasticNet. Преобразование включено в пайплайны ElasticNet и Ridge |
| Удаление `Street` | Проверка, полезен ли почти константный признак типа покрытия улицы | У CatBoost RMSE вырос с `0.118453` до `0.120311`. Признак оставлен |
| Удаление `PoolArea` и `PoolQC` | Проверка, полезны ли площадь и качество бассейна, который есть только у 7 домов в трейне | У CatBoost RMSE вырос до `0.120053`. Оба признака оставлены |
| Порядковое кодирование `KitchenQual` | Кодирование качества кухни от плохого к отличному через `OrdinalEncoder` | У ElasticNet RMSE вырос с `0.135302` до `0.135643`. Оставлен one-hot |
| Порядковое кодирование `ExterQual` | Кодирование качества наружных материалов через `OrdinalEncoder` | У ElasticNet RMSE вырос с `0.135302` до `0.135435`. Оставлен one-hot |
| `GrLivArea` и `log1p(GrLivArea)` вместе | Проверка, полезно ли сохранить исходную надземную жилую площадь вместе с её логарифмом | RMSE немного вырос у Ridge и ElasticNet. В обоих пайплайнах оставлен только логарифм площади |


## Модели и эксперименты

Бейзлайн - ElasticNet. Также реализованы Ridge, KNN, Decision Tree, Random Forest, CatBoost, LightGBM, MLP и MLP с категориальными эмбеддингами.

В экспериментах с нейросетями проверялись число и размеры скрытых слоёв, BatchNorm, Dropout, функции активации, оптимизаторы, регуляризация, learning rate, размер батча и число эпох.
Для подбора гиперпараметров использовал поиск по сетке и ближе к концу проекта попробовал Optuna.
В проверенных конфигурациях scheduler не улучшил validation rmse и validation loss, поэтому в финальной версии не используется. Проверялись: косинусовый, ступенчатый, а также warm-up с последующим косинусовым снижением.
После экспериментов с early stopping сравнил средний RMSE пяти фолдов на каждой общей эпохе. Так выбрал 151 эпоху для MLP и 247 для MLPEmb.
По Kaggle score лучшими одиночными моделями оказались CatBoost (0.12204), LightGBM (0.12505), ElasticNet (0.12697).

### Валидация

Используется `K-Fold`; число фолдов и seed задаются в конфиге. В базовой конфигурации - 5 фолдов и seed 67. Основная метрика сравнения - rmse.

Для averaging используются OOF предсказания: каждое предсказание получено моделью, которая не обучалась на соответствующей строке. Для оценки стекинга используется вложенная CV: внутренние OOF-предсказания обучают метамодель, затем базовые модели переобучаются на всей обучающей части внешнего фолда и предсказывают его валидационную часть.

### Ансамбли

- **Averaging:** среднее предсказаний CatBoost, LightGBM.
- **Stacking:** метамодель Ridge на двух OOF-предсказаниях.

## Настройка экспериментов

Все настройки находятся в [config.py](config.py).

| Раздел / параметр | Назначение |
|---|---|
| `general.experiment_name` | Префикс создаваемых файлов и записей в логах |
| `general.train` | Запуск обучения и валидации |
| `general.inference` | Запуск предсказаний из сохранённых моделей |
| `to_train` | Выбор моделей и ансамблей для обучения / оценки |
| `to_grid_search` | Включение поиска по сетке для выбранных моделей |
| `models`, `dl_train` | Параметры моделей и обучения нейросетей |
| `general.train_dl_on_all_data` | Дополнительное обучение нейросетей на всей обучающей выборке |
| `general.save_models` | Сохранение моделей и препроцессоров |
| `general.save_logs`, `general.show_logs` | Сохранение и подробный вывод результатов экспериментов |
| `general.save_oof` |  Запись новой OOF-таблицы в CSV, когда для ансамбля обучаются оба бустинга |
| `paths.OOF_PREDS` | Путь для записи / чтения OOF-таблицы предсказаний |
| `to_inference` | Выбор моделей и ансамблей для инференса |
| `inference` | Имена сохранённых моделей, загружаемых при инференсе |
| `models.stacking.cv` | Включение вложенной CV стекинга |

### Только инференс

Нужно установить `general.train=False`, `general.inference=True` и включить нужные флаги в `to_inference`. 
Для готовых моделей используется имя `FINAL_название_модели` в разделе `inference`.

### Обучение своих моделей

Нужно установить `general.train=True`, выбрать модели в `to_train` и задать их параметры. Для нейросетей полное обучение включается через `train_dl_on_all_data`. Чтобы сохранить результат, нужно включить `save_models`.

Новые файлы получают имя текущего эксперимента. Чтобы использовать их в последующем инференсе нужно обновить соответствующие имена в разделе `inference`. Флаг `save_models` не переключает инференс на новые файлы.

Для оценки стекинга нужно включить `to_train.stacking` и `models.stacking.cv`. Если CV выключена, Ridge только обучается на OOF-таблице и при необходимости сохраняется.

Итоговая таблица включает и RMSE рассчитанных ансамблей. show_logs управляет подробным выводом базовых моделей, а результаты ансамблей добавляются в общую таблицу независимо от этого флага.

## Структура проекта

```text
main.py                 # точка запуска
config.py               # конфигурация
dataset.py              # загрузка данных и создание признаков
preprocessing.py        # препроцессоры и подготовка входов MLPEmb
optimizer.py            # создание оптимизаторов
inference.py            # инференс моделей и ансамблей
artifacts.py            # сохранение и загрузка артефактов, логов и CSV
visualization.py        # графики обучения
EDA_House_Prices.ipynb  # анализ данных и выводы
requirements.txt        # зависимости
dl_models/              # архитектуры MLP и MLPEmb
train/                  # обучение и управление экспериментами
validation/             # CV, OOF, поиск по сетке и оценка стекинга
data/                   # исходные train.csv и test.csv
saved_models/           # сохранённые модели, препроцессоры и logs.txt
oof_preds/              # сохранённые OOF-прогнозы
inference_predicts/     # создаваемые CSV для Kaggle
```

Файлы `FINAL_*` предназначены для запуска готового решения. Включённый в репозиторий `logs.txt` оставлен пустым для записей новых экспериментов.
